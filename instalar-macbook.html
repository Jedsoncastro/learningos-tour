Uma vez em cada Mac

Instalar o LearningOS no MacBook Air

Passo a passo para deixar o MacBook Air igual ao Mac mini: rodar o app com seus materiais e continuar construindo o projeto pelos dois. O código fica no GitHub e passa de um Mac para o outro.

30 a 60 minutos, quase tudo download Pede a senha do Mac algumas vezes Script testado no Mac mini em 26/11/2026

Antes de começar

1Instalar o Homebrew (no Air)

O Homebrew é o "instalador de programas" que o script usa para baixar o resto.

  1. Aperte Cmd + Espaço, digite Terminal e aperte Enter.

  2. Cole este comando e aperte Enter. Ele pede a senha do Mac e depois Enter para confirmar.

    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

    Leva de 5 a 15 minutos. Pode instalar também as "Command Line Tools" da Apple: aceite.

  3. Quando terminar, cole este outro comando para o Terminal passar a enxergar o Homebrew:

    echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile && eval "$(/opt/homebrew/bin/brew shellenv)" && brew --version

    Deu certo se aparecer Homebrew e um número de versão.

2Entrar no GitHub (no Air)

O projeto é privado. Sem este login, o Air não consegue baixar o código.

  1. Cole e aperte Enter:

    brew install gh && gh auth login

  2. Responda assim, usando as setas e Enter: GitHub.com, depois HTTPS, depois Yes, depois Login with a web browser.

  3. O Terminal mostra um código de 8 letras. Aperte Enter, o navegador abre: entre na sua conta do GitHub, cole o código e autorize.

3Copiar a chave da IA (no Mac mini)

A chave da IA não fica no GitHub, de propósito. Este comando copia a chave do Mac mini para a área de transferência, e ela aparece no Air pela mesma conta Apple, sem criar arquivo nenhum.

  1. No Mac mini, abra o Terminal, cole e aperte Enter. Não aparece nada na tela: é normal.

    grep '^ANTHROPIC_API_KEY=' ~/Developer/learningos/.env | cut -d= -f2- | pbcopy

  2. Faça o passo 4 logo em seguida, em até 2 minutos. Depois de colar no Air, copie qualquer outra coisa no Mac mini para a chave sair da área de transferência.

Se a cópia não passar de um Mac para o outro, confira se os dois estão com Bluetooth, Wi-Fi e Handoff ligados (Ajustes do Sistema, Geral, AirDrop e Handoff). Ou pule a chave: o app funciona com IA simulada e dá para colocar a chave depois.

4Baixar o projeto e instalar tudo (no Air)

  1. Cole este comando inteiro e aperte Enter:

    mkdir -p ~/Developer && cd ~/Developer && { [ -d learningos ] || gh repo clone castro-ai-labs/learningos; } && cd learningos && git pull --ff-only && bash scripts/instalar-mac.sh

    Ele mostra 7 etapas, cada item com [ok] quando fica pronto: Homebrew, ferramentas, Node, Supabase, pacotes do projeto, chaves e banco.

  2. Na etapa 6 ele pede a chave: aperte Cmd + V e depois Enter. A chave não aparece na tela, de propósito.

  3. Na etapa 7 ele instala e abre o Docker. Na primeira vez, aceite os termos na janela do Docker (pode pular o cadastro). O script espera até 5 minutos o Docker ficar pronto.

  4. No final aparece PRONTO. A instalação acabou.

Pode rodar o mesmo comando de novo quando quiser: o que já está pronto é pulado. Para só conferir, sem mudar nada: bash scripts/instalar-mac.sh --conferir

5Usar o app no Air

Daqui em diante é igual ao Mac mini: abra o Docker, ligue o app pelo Terminal e abra localhost:3000. O roteiro completo está no guia da demonstração, a partir do passo 1.

Cada Mac tem o seu próprio banco. A conta e os materiais que você criar no Air ficam só no Air; os do Mac mini, só no Mac mini. Para ter os mesmos dados nos dois e no celular, o app precisa ser publicado na internet, o que ainda depende da sua decisão sobre hospedagem e custo.

6Continuar construindo pelos dois Macs e pelo celular

  1. Claude Code no Air: instale o seu kit (skills, regras e proteções), pelo arquivo INSTALAR-NO-MAC-2.md do repositório meu-kit-claude. Assim o Air trabalha com as mesmas regras do Mac mini.

  2. Ao começar a trabalhar num Mac, abra o Claude Code na pasta do projeto e peça: "puxa as novidades do GitHub". Ele traz o que foi feito no outro Mac.

  3. Ao terminar, peça: "salva no GitHub". Sem isso, o outro Mac não vê o que foi feito.

  4. Evite mexer no mesmo assunto nos dois Macs ao mesmo tempo. Termine e salve num, depois continue no outro.

  5. No celular: no app Claude, a aba Code trabalha direto no projeto do GitHub, na nuvem. Dá para pedir mudanças, acompanhar e aprovar os pacotes de mudança (PRs). O que não dá é ligar o app no celular: ele precisa do Docker, que só roda no Mac.

O que não passa sozinho de um Mac para o outro: o banco (contas e materiais), a chave da IA (passo 3) e as anotações que o Claude guarda sobre este projeto no Mac mini. As regras e decisões importantes já estão no próprio projeto, então o Air começa sabendo o essencial.

Se algo der errado

O que apareceO que fazer
"command not found: brew" ou "gh"Feche o Terminal (Cmd + Q), abra de novo e repita o comando. Se continuar, refaça o passo 1.
"Could not resolve to a Repository" ou pedido de senha do GitHubO login do passo 2 não foi feito ou foi com outra conta. Rode gh auth login de novo.
Uma linha começando com PAROU:O script explica o motivo nessa linha. Faça o que ela pede e rode o comando do passo 4 de novo.
"isso nao parece uma chave da Anthropic"A cópia do passo 3 não chegou. Refaça o passo 3 e rode o passo 4 de novo. Nada foi gravado.
"o Docker nao ficou pronto"Abra o app Docker, aceite os termos e espere a baleia no alto da tela parar. Depois rode o passo 4 de novo.
Se o mesmo erro aparecer duas vezes, pare e me mande um print do Terminal.
